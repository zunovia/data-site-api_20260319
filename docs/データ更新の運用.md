# データ更新の運用

このサイトは統計を載せている。統計は古くなる。
古いまま置いておくと、営業資料に転記された数値が事実と違う、という形で跳ね返る。
そこで「月に1回、必ず出典を見に行く」仕組みを入れた。その説明。

---

## 大原則：更新日を、確認日と混同しない

| 表示 | 意味 | いつ進めるか |
|---|---|---|
| **最終更新** | ページの数値が実際に変わった日 | 数値を書き換えたときだけ |
| **最終確認** | 出典を見に行った日 | 見に行くたび。変化が無くても進める |

**中身が変わっていないのに「最終更新」を進めてはいけない。**
読む人に「新しい情報だ」と誤解させることになる。
「常に更新しているように見せる」のではなく、「常に確認していることを正しく見せる」。
そのために2つを分けている。

---

## 仕組みの全体像

```
data/sources.json          ← 出典の台帳。ここが唯一の出所
        │
        ├─ scripts/check_freshness.py        期限が来た出典を洗い出す（Webは見ない）
        │        └─ .github/workflows/monthly-data-check.yml
        │                 毎月2日 7:00 JST に走り、期限到来があれば Issue を立てる
        │
        └─ js/freshness.js                   各ページに 最終更新／最終確認 を表示
```

- **自動でやること**：期限の検知、Issue の作成、ページ上の日付表示
- **人（またはClaude）がやること**：実際に一次情報を読み、数値を差し替える

判断が要る部分は自動化していない。統計の読み違いをそのまま公開すると取り返しがつかないため。

---

## 毎月の手順

1. Issue「データ鮮度の点検 YYYY-MM」が立つ（立たなければその月は何もしなくてよい）
2. Issue に並んだ出典を実際に開く
3. **新しい調査が出ていた場合**
   - 該当ページの数値・注釈・グラフのデータを差し替える
   - `data/sources.json` の `as_of` / `next_expected` / `last_updated` / `last_checked` を更新
   - `confidence` を見直す（`confirmed` / `estimated` / `stale`）
4. **出ていなかった場合**
   - `last_checked` **だけ**を今日の日付にする
   - `next_expected` を次の想定時期にずらす
   - `last_updated` は**動かさない**
5. コミットして push（GitHub Pages に自動反映）

手元で確認するとき:

```bash
python scripts/check_freshness.py            # 人が読む形
python scripts/check_freshness.py --markdown # Issue 本文と同じ形
```

---

## 台帳（data/sources.json）の項目

| キー | 意味 |
|---|---|
| `key` | ページの識別子。`js/freshness.js` の `data-page` と一致させる |
| `last_updated` / `last_checked` | 上記の大原則のとおり |
| `needs_inventory` | 出典・調査年が特定できていないページ。`true` の間はページにバッジが出る |
| `sources[].as_of` | いま載せている数値の調査時点 |
| `sources[].cadence_months` | 公表の周期。`0` は常時取得（e-Stat API 等・点検対象外） |
| `sources[].next_expected` | 次に新しい版が出ると見込む年月。`null` なら点検しない |
| `sources[].confidence` | `confirmed`（一次情報で確認） / `estimated`（推計） / `stale`（後継調査なし） / `unknown`（未確認） |

期限の1か月前から Issue に載る（`scripts/check_freshness.py` の `LEAD_MONTHS`）。

---

## 棚卸しが残っているページ

`needs_inventory: true` のページは、載せている数値の出典と調査年が特定できていない。
1ページずつ、次の順で埋める。

1. ページ内の数値を洗い出す
2. それぞれの出典（機関・調査名・調査年）を特定する
3. `sources.json` に書き、`needs_inventory` を `false` にする
4. 出典が特定できない数値は、ページから消すか `参考値` と明示する

対象: 年収 / 人口 / 医療・脳疾患 / NPO・寄付 / 政治・選挙 / 暮らし

---

## 注意していること

- **選挙のあった月は、政治ページを必ず確認する。** 周期ではなくイベントで動くため、
  `next_expected` に頼れない。
- **法人向けのクラウド会計調査は2017年で止まっている。** 毎月「後継が出ていないか」だけ
  確認し、出ていなければ `stale` のままにする。無理に推計で埋めない。
- **数値を変えたら、その根拠のURLも一緒に更新する。** 出典が辿れない数値は載せない。
